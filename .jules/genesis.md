## 2024-05-24 — Auto-Retry with Exponential Backoff for External APIs
**Failure point found:** Direct, unprotected `fetch()` calls to external AI APIs (Gemini, DeepSeek, Bhashini, Ollama) in `server.js`. Any transient network failure, timeout, or rate limiting (HTTP 429) would cause an immediate hard failure, returning a 500 status to the client and breaking the chat experience.
**Why it existed:** The original implementation prioritized getting the MVP working quickly. Error handling was limited to catching the failure and either responding with an error or triggering a failover cascade, but it completely lacked self-healing transient retries for the individual API calls themselves.
**Recovery built:** Implemented `fetchWithRetry`, an automatic retry mechanism with exponential backoff. It wraps all external API calls. It automatically retries on 5xx server errors, 429 rate limits, and network errors, waiting `100 * Math.pow(2, attempt - 1)` milliseconds between attempts. It properly handles explicit aborts (`AbortError`) to avoid retrying canceled requests and explicitly consumes the response body of failed requests to prevent memory leaks.
**Blast radius before:** High. Any momentary network blip, container cold start, or brief API rate limit would disrupt the user's workflow, forcing them to manually retry or losing context entirely.
**Watch for:** Other unprotected network boundaries, especially database calls or newly added third-party integrations (like payment gateways or PDF parsers) that might be introduced without utilizing the new `fetchWithRetry` utility.
