## 2026-07-04 — Logging Data Exfiltration Prevented
**Data traced:** PII (Email, SSN, Credit Cards) and Secrets (API Keys, Passwords, Tokens)
**Exposure found:** `server.js` was using `console.log`, `console.error`, and `console.warn` everywhere. These outputs bypassed any filtering and dumped raw payloads (e.g., API keys in the `/api/chat` body, explicit user requests) directly to standard output and could be collected by any container logging daemon. `req.body` containing sensitive keys and `latestUserMessage` containing plaintext user PII was printed directly to logs via template strings.
**Fix:** Introduced a structural custom Winston format `redactFormatter`. This deeply clones all log payloads (protecting original objects from mutation), correctly preserves Symbols and `Error` prototypes (which winston relies on), and runs regex masking over string values to hide PII (Emails, SSNs, CCs). Key-level redaction filters out `password`, `token`, `apiKey`, etc. Replaced all `console.*` calls with `logger.*`, and refactored logging statements to pass dynamic data in the `meta` object rather than string interpolation, preventing regex bypass.
**Coverage confirmed:** Ran a local HTTP test against the RAG backend simulating a malicious payload containing an email, CC, SSN, and apiKeys. Confirmed the standard output only contained masked data (e.g. `t***@gmail.com`) and `[REDACTED]`.
**Still exposed elsewhere:** The DB vector store embeddings themselves may contain PII extracted directly from uploaded docs, which has not been addressed.
