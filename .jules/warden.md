## 2026-07-07 — Application and Error Logs Redaction
**Data traced:** PII (Email, Phone, SSN, Credit Card, Passwords)
**Exposure found:** `server.js` previously used native `console.log` and a basic Winston logger that did not redact any application logs or request bodies. Native console methods logged directly to the process output without filtering, making sensitive request payloads (like auth forms containing emails/passwords or chat logs containing PII) visible in plaintext logs.
**Fix:** Created a custom Winston formatting layer (`deepRedact`) that traverses objects, strips sensitive keys (`email`, `ssn`, `password`, `creditcard`, `cardnumber`, `phone`), and applies regex masking to string values for Emails (partial masking `j***@gmail.com`), SSNs (`***-**-6789`), and Credit Cards (`****-****-****-3456`) across all logged data. Replaced the `server.js` logger configuration with this formatter and globally intercepted `console.log`, `console.warn`, and `console.error` to pipe through the redacted Winston logger instead of stdout/stderr, ensuring the redaction traverses arguments *before* stringification, and safely preserving non-standard `Error` properties.
**Coverage confirmed:** The `deepRedact` function securely traverses objects using a `WeakSet` to prevent circular reference crashes, ensuring entire request payloads can be safely dumped into logs. Native `console` methods now output sanitized JSON to the log transports.
**Still exposed elsewhere:** The system does not currently feature a mechanism to permanently delete a user's vectorized documents or chat histories from the backend if a data removal request is issued (structural deletion gap). Exports in UI currently allow users to download complete, unredacted session texts.
