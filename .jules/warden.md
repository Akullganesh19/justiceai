## 2025-02-23 — [Logging Exposure Fix]
**Data traced:** User inputs / prompts in `/api/chat` route, payload objects passed to logger that might contain sensitive fields.
**Exposure found:** `server.js` was truncating and logging the user's latest prompt directly using `console.log` (exposing any sensitive information in the first 50 chars). Multiple routes (Bhashini, Chat, Global Error Handler) were catching generic exceptions and returning unredacted `err.message` values directly to the client as JSON responses, leaking potential PII or internal server structure variables conditionally. Unredacted logs were passed via `console.error`.
**Fix:** Created a `redactLog` Winston formatter leveraging a `WeakSet` traversal to iteratively mask common patterns (email, SSN) and specific PII keys (`email`, `password`, `creditCard`, `ssn`, `phone`) without throwing circular reference errors. Substituted `console.error` with `logger.error` using the formatter. Removed `console.log` for chat prompts. Replaced client error outputs with standard generic `Internal Server Error` strings.
**Coverage confirmed:** Tested triggering server exceptions via POST requests on `/api/chat` using missing APIs; verified response hides actual traces by providing `{ "error": "Internal Server Error" }`. Directly verified Winston `redactLog` execution against heavily mocked object permutations demonstrating circularity handling, object mutation blocks, and masking properties cleanly in `winston_test.log`.
**Still exposed elsewhere:** Currently frontend local storage persists user prompts/chat history locally (localStorage cache in browsers) in non-encrypted plain text. Bhashini external API proxy sends out raw data externally without prior redaction.
