## 2026-08-29 — PII Leak in Server Logs

**Data traced:** Emails, Phone Numbers, Social Security Numbers (SSN), Credit Card Numbers, and raw user conversational history.
**Exposure found:** `server.js` was heavily utilizing standard `console.log` and `console.error` for extensive request debugging. The `/api/chat` POST route explicitly printed `latestUserMessage.substring(0, 50)` and error catch blocks printed raw error objects (which often contained LLM system prompts or user payloads) to STDOUT without any sanitization.
**Fix:** Introduced a generic `redactFormat` into the application's `winston` logger configuration. The formatter recursively scans all outgoing string logs (both the primary message string and inner JSON metadata fields) for PII patterns using regex, replacing matching data with masked asterisks (e.g., `j***@example.com` or `***-**-6789`). Converted all relevant `console.log` and `console.error` statements to `logger.info` and `logger.error` to ensure the masking format is strictly applied to all standard STDOUT paths.
**Coverage confirmed:** Visually confirmed via `git diff` that the Winston logger is instantiated with `redactFormat` and the raw `console.*` outputs are replaced by `logger.*`. Tested logic on standalone isolated script.
**Still exposed elsewhere:** There are still `console.warn` calls active inside `server.js` (used primarily inside fallback/error catch blocks like the document parser). There are also `localStorage` entries (e.g. `justice_ai_history`) persisting chat logs indefinitely on the client side without automated expiry logic.
