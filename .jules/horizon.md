## 2024-07-07 — Global CustomEvent Migration to React Context
**Risk identified:** The application used a raw, global `window.dispatchEvent` and `window.addEventListener` ('justice-ai-transcription') to communicate state changes across disparate components (from the `FloatingVoiceButton` or `main.jsx` wrapper into `ChatInput`). This pattern bypasses React's declarative state management, causes hidden coupling, risks memory leaks if not cleaned up precisely, and can trigger unpredictable, un-batched re-renders, which would scale poorly as more cross-component events are introduced.
**Migration target:** The ecosystem is firmly seated in declarative Context-based or hook-based state management tools for app-wide cross-cutting concerns.
**Migrated this session:** Built a `TranscriptionContext` provider in `src/components/voice/TranscriptionContext.jsx`. Bound the global `window` event to state within this single Provider, and migrated `src/components/chat/ChatInput.jsx` to consume it via a custom `useTranscription` hook, ensuring rapid sequential events update reliably via an incrementing timestamp counter.
**Remaining:** `FloatingVoiceButton` still dispatches via a prop callback routed up to `main.jsx` and fired as a raw CustomEvent. We need to invert this so that either `FloatingVoiceButton` uses the context directly (or the context provider exposes an `updateTranscription` dispatch function), completely eliminating the need for `CustomEvent` altogether.
**Next session:** Add an `emitTranscription` function to the `TranscriptionContext`, migrate `FloatingVoiceButton.jsx` to use it, and remove the `CustomEvent` dispatch entirely from `src/main.jsx`.
