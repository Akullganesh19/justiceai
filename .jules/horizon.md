## 2024-05-24 — Migrate Global CustomEvents to React Context
**Risk identified:** The application relies on global DOM `CustomEvent`s (e.g., `justice-ai-transcription`) dispatched via `window.dispatchEvent` for loosely-coupled cross-component state sharing (like sending voice transcriptions to chat inputs). This approach lacks type safety, breaks idiomatic React patterns, makes state flow opaque (event listeners can be anywhere), and causes subtle bugs around unmounted components or replay vulnerabilities. As the codebase scales, this "Event Bridge" pattern will become increasingly difficult to debug and maintain.
**Migration target:** React Context API for global, shared state management. This aligns with modern, idiomatic React architecture, providing explicit dependency injection, strong typing, predictability, and better integration with hooks and suspense boundaries.
**Migrated this session:** Migrated the `justice-ai-transcription` global CustomEvent flow. Created `TranscriptionContext.jsx`, wrapped the app in `TranscriptionProvider` in `src/main.jsx`, updated `FloatingVoiceButton` to use `setGlobalTranscription` directly instead of a prop or an event, and updated `ChatInput` to consume the global state using a timestamp-based `useRef` to prevent replay bugs on remount.
**Remaining:** Migrate any other global `CustomEvent` usages (if any exist beyond navigation/keyboard shortcuts) to dedicated contexts. Investigate other loosely-coupled states using `localStorage` syncing where an in-memory Context might be more appropriate for cross-tab or component sync.
**Next session:** Identify and migrate the next highest-risk CustomEvent or localStorage-driven synchronization pattern.
