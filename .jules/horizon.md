## 2024-05-18 — Migrate CustomEvent Event Bridge to Context API
**Risk identified:** The global `window.dispatchEvent` / `addEventListener('justice-ai-transcription')` implementation pattern for cross-system communication (from `FloatingVoiceButton` to page inputs like `ChatInput`) represents an unmaintainable legacy decision. Global CustomEvents for standard UI state sharing tightly couple otherwise independent components without type-safety, testability, or traceability, scaling poorly as application complexity grows and causing hard-to-track replay bugs on remount.
**Migration target:** The React Context API. Centralizing the transcription state inside a `TranscriptionContext` prevents namespace collision, properly manages component lifecycles, and integrates easily with React's natural rendering cycle.
**Migrated this session:** Created `TranscriptionContext` to manage `{ text, timestamp }` state. Removed global event dispatcher from `src/main.jsx`, wrapped the app in `TranscriptionProvider`, and refactored `FloatingVoiceButton` usage. Updated `ChatInput` to consume the context using the `useTranscription` hook, utilizing a `useRef` to track event consumption and prevent replay bugs on remount.
**Remaining:** Check if there are other components listening to 'justice-ai-transcription' (e.g., other page inputs) and migrate them to consume `useTranscription` if they exist. Standardize usage of `TranscriptionProvider` for any new inputs needing voice transcription.
**Next session:** Investigate if there are other global CustomEvents currently utilized for state-sharing (like `justice-ai-history`, etc) that could be migrated to properly scoped Contexts or local state.
