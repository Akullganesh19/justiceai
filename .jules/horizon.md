## 2024-05-24 — [Migrate Global CustomEvents to React Context API]
**Risk identified:** The application relies on `window.dispatchEvent` with DOM `CustomEvent` (`justice-ai-transcription`) to share tightly coupled UI state (transcriptions from the floating voice button to the chat input). This breaks React principles, makes state untraceable, lacks type-safety, and violates future-proofing goals, making the app harder to scale and test as more components depend on shared state.
**Migration target:** Migrate to the React Context API to provide a robust, idiomatic, testable, and traceable way to share global state across the component tree without side effects on window objects.
**Migrated this session:** Created `TranscriptionContext.jsx` and wrapped the main router in `src/main.jsx`. Replaced `window.dispatchEvent` in `FloatingVoiceButton` with `addTranscription` from the Context. Replaced `window.addEventListener` in `ChatInput` with `useTranscription`, properly tracking the update IDs via `useRef` to avoid component remount "replay bugs".
**Remaining:** Migrate any other remaining `CustomEvent` usages in the codebase (such as `KeyboardEvent` dispatches in error pages or potentially local storage syncing logic) to Context API or custom hooks where appropriate.
**Next session:** Identify and migrate remaining global event listeners (like keyboard event command palette triggers) that can be better handled via explicit React state or context.
