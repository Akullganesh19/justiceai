## 2026-06-22 — CustomEvent to Context API / Global State Migration
**Risk identified:** The application relies on native DOM `CustomEvent` (`justice-ai-transcription`) dispatched globally on the `window` object to manage global state communication (e.g. between FloatingVoiceButton and ChatInput). This pattern becomes brittle, hard to test, type-unsafe, and difficult to trace as the app grows. It skirts React's state management paradigms entirely, leading to hidden coupling and a higher likelihood of memory leaks or race conditions if event listeners aren't perfectly managed. In 2-3 years, as this app scales into a more complex modular architecture, tracing these global DOM events will become a significant debugging nightmare and onboarding hurdle.
**Migration target:** The React ecosystem settled long ago on Context API (for simple/infrequent global state) or dedicated state managers (Zustand, Redux, Jotai) for cross-component communication. Given the localized nature of voice transcription, React Context is the perfect, native, scalable solution.
**Migrated this session:** Replaced the `CustomEvent` for global voice transcription (`justice-ai-transcription`) with a dedicated React Context (`VoiceTranscriptionContext`). Updated `main.jsx`, `FloatingVoiceButton`, and `ChatInput` to use this Context instead of `window.dispatchEvent` and `window.addEventListener`.
**Remaining:** Identify any other usages of `CustomEvent` or raw `window.addEventListener` for application state and migrate them to Context or local state.
**Next session:** Look for other native DOM event usage for app state and migrate to proper React patterns.
