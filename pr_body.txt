## 🔭 Future-Proofing Migration

**What:** Migrated global transient voice transcription state from native DOM `CustomEvent`s (`window.dispatchEvent`) to the React Context API (`TranscriptionContext`).
**Risk it eliminates:** The legacy approach tightly coupled disconnected components via the global window object, bypassing React's rendering lifecycle and type-safety mechanisms. This causes untraceable state updates, race conditions (synchronous vs asynchronous loops), and "replay bugs" on remounts that get progressively harder to debug as the app scales.
**Why now:** Moving out of a transient DOM event architecture to React native state early prevents technical debt from compounding, making the application more maintainable for future developers. Re-writing state flows is vastly simpler now before more components rely on `justice-ai-transcription`.
**Migration approach:** Employed an **additive migration** strategy. Introduced `TranscriptionContext` and an intermediate `GlobalVoiceBridge` component inside `src/main.jsx`. The bridge acts as an adapter, pushing new transcriptions into the React Context state *while simultaneously* continuing to dispatch the legacy `CustomEvent`. `ChatInput` was updated to consume the Context via a custom `useTranscription` hook and a timestamp ref to prevent replay issues. The legacy event listener in `ChatInput` was safely removed.
**Remaining:** Identify if there are any other consumers of the legacy `justice-ai-transcription` event and migrate them to Context. Once the legacy event is completely obsolete, remove the `window.dispatchEvent` fallback from the `GlobalVoiceBridge`.
