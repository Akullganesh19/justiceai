## 🔭 Future-Proofing Migration

**What:** Migrated voice transcription state sharing from brittle global DOM `CustomEvents` (`window.dispatchEvent`) to a React `Context` (`TranscriptionContext`).
**Risk it eliminates:** The legacy approach relied on implicit, untyped global events that break React's data flow, are difficult to test without heavy mocking, and are highly susceptible to memory leaks and replay bugs on component remount. This pattern would become significantly more painful to refactor as more components started relying on the voice feature.
**Why now:** Technical debt deferred is technical debt compounded. The global event pattern is fundamentally at odds with modern React architecture. It was already starting to spread from `FloatingVoiceButton` to `ChatInput`. Migrating it now while the surface area is relatively small makes the transition smooth.
**Migration approach:** We adopted an additive migration strategy. A new `TranscriptionContext` was introduced and wrapped around the application in `src/main.jsx`. An inner `GlobalVoiceManager` was created to dispatch the transcription text to *both* the new Context API and the legacy `window.dispatchEvent`. The `ChatInput` component was updated to prioritize reading from the new Context (using a `useRef` to track event timestamps and prevent replay bugs), while keeping a fallback listener for the legacy event to ensure zero downtime.
**Remaining:** Migrate any other components (e.g., search bars, other input fields) that might still be relying on `window.addEventListener('justice-ai-transcription')` to instead use the `useTranscription()` hook. Once all consumers are updated, the legacy dispatch in `src/main.jsx` and the fallback listeners in the components can be safely removed.
